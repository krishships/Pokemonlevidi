# Grafting onto `pret/pokeemerald`

This repo is the hack's *own* code. The engine it builds on lives in a separate
checkout of `pret/pokeemerald`, pinned to a known-good commit. Nothing here
copies engine code, so the two can be updated independently.

## One-time setup

```bash
git clone https://github.com/pret/pokeemerald.git base/pokeemerald
cd base/pokeemerald && git checkout <PINNED_COMMIT> && cd ../..
```

`base/` is git-ignored on purpose — it is a dependency, not part of this repo.

You also need a **ROM base** you own: dump your own `pokeemerald.gba` from a
cartridge and place it at `base/pokeemerald/pokeemerald.gba`. It is git-ignored
and must never be committed or uploaded. CI takes it from a repository secret
(`AB_ROM_BASE64`), which you should only add to a private repo you control.

## Graft

```bash
bash tools/graft.sh
```

which does, in order:

1. copies `include/*.h` (the core API, the bridge header) and
   `include/generated/` into `base/pokeemerald/include/`
2. copies `src/action_battle.c`, `src/generated/`, `src/pokeemerald/` into
   `base/pokeemerald/src/`
3. applies every `patches/*.patch` with `git apply`

**No Makefile edit is needed.** pokeemerald globs its sources:

```make
C_SRCS_IN := $(wildcard $(C_SUBDIR)/*.c $(C_SUBDIR)/*/*.c $(C_SUBDIR)/*/*/*.c)
```

so `src/action_battle.c`, `src/generated/bosses_data.c` and
`src/pokeemerald/ab_bridge.c` are picked up automatically (two subdirectory
levels are covered — do not nest deeper than that).

Build:

```bash
bash tools/build_rom.sh      # → dist/heart-and-soul.gba
```

## Toolchain

| Path | Toolchain | Notes |
| --- | --- | --- |
| Default | `agbcc` (`./build_tools.sh`) | matches the retail ROM's codegen |
| Modern | `arm-none-eabi-gcc` + `MODERN=1` | faster, needed for C11 features |

The core is plain C11 with no libc beyond `<string.h>`, so it builds under
either. It has no `malloc`, no floats, and no 64-bit arithmetic on the hot path.

## Hook points

| File in pokeemerald | Status |
| --- | --- |
| `src/battle_main.c` — `BattleTurnPassed()` | **done**, by `patches/0001-live-battle-turn-hook.patch` |
| `include/battle.h` | not needed yet — the bridge keeps its own state |
| `src/battle_script_commands.c` | not needed: the turn script never runs because `BattleTurnPassed` returns before it |
| `src/item_use.c` / party menu | **todo** — `ITEM_POKE_FLUTE` has no out-of-battle handler in the base ROM, so the item needs a case adding to the party-menu item dispatch before it can start an arena |
| `src/overworld.c` | **todo** — nothing to restore yet, the arena does not replace the field |
| `data/battle_scripts_1.s` | not needed: `gBattleOutcome` is set directly, so the stock win/whiteout path runs |

### The one hook

```c
void BattleTurnPassed(void)
{
    s32 i;

    // Pokemon Heart and Soul: real-time action battle.
    if (gBattleOutcome == 0 && AbBridge_Tick())
        return;

    TurnValuesCleanUp(TRUE);
    ...
```

`BattleTurnPassed` is reached through `gBattleMainFunc`, called once per frame
from `BattleMainCB1`. Returning early keeps `gBattleMainFunc` pointing at
`BattleTurnPassed`, so the core ticks at a steady 60 Hz and the turn machinery
below never advances. When the fight resolves, `AbBridge_Tick` sets
`gBattleOutcome` and returns `FALSE`, letting the engine's own end-of-battle
handling run unchanged.

If you ever see the fight running at half speed, the engine is calling
`gBattleMainFunc` from a different callback than you think — check
`BattleMainCB1` before changing anything in the core.

## Frame budget on hardware

The GBA has ~280k cycles per frame. The core costs a few hundred cycles per
entity per tick; the real cost is OBJ count and DMA. Keep the boss to one
composite sprite plus one hitbox flash, and cap active projectiles at 8.

## What is verified, and what is not

Verified against `pret/pokeemerald` @ `9103e52`:

- `patches/0001-live-battle-turn-hook.patch` applies cleanly on a fresh clone
- every engine symbol the bridge uses exists in the tree (`JOY_HELD`, `JOY_NEW`,
  `ARRAY_COUNT`, `TRAINER_ID_LENGTH`, `gSaveBlock2Ptr`, `FlagSet`,
  `StringCompare`, `gTrainerBattleOpponent_A`, `gBattleOutcome`,
  `B_OUTCOME_WON/LOST`, `FLAG_UNUSED_0x020`–`0x025`)
- `gBattleMainFunc()` is called once per frame from `BattleMainCB1`

**Not verified:** the bridge has not been compiled for ARM. A full
`-fsyntax-only` pass stops at `map_groups.h`, which is generated by the build
and does not exist in a bare clone, so a real compile needs the toolchain, the
generated headers and a base ROM. Expect the first `make` to surface small
type warnings; they will be in `ab_bridge.c`, not in the core.

## Order of work

1. Graft the core, build, boot — the ROM should still play normally with the
   flag off. **Do not** wire the AI in yet.
2. Wire the bridge with a debug key that starts a live battle from the field.
3. Convert one arena (Sentinel of Ash) end to end: entry, camera, HUD, win,
   loss.
4. Only then add the remaining five bosses.

## If this repo is public

Do not add `AB_ROM_BASE64` to a public repository. Keep `AB_ENABLE_ROM_BUILD`
unset, or keep the ROM build in a private mirror and push only source here. The
`rom-build` job is gated to manual `workflow_dispatch` runs for exactly this
reason: a pull request must never be able to reach a base ROM.
